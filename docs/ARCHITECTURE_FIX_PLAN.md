# A股量化系统 - 架构问题分析与修复方案

## 📋 执行摘要

**发现问题**：
1. 缓存过期机制不完善（仅5分钟短缓存，无夜间更新）
2. 多数据源架构存在漏洞（基本面数据无多源，AKShare被移除）
3. ETF基金代码识别错误（已修复）

**解决方案**：
1. 建立三级缓存体系 + 夜间更新任务
2. 恢复并优化多数据源获取
3. 统一数据获取接口

---

## 🔍 问题1：缓存过期机制

### 现状
```python
# 当前只有5分钟短缓存
if elapsed_minutes < 5:
    return cached.get('data')
```

### 问题
- 技术指标（MA、20日高低点）每天只需要计算一次
- 基本面数据（PE/PB/ROE）每季度更新一次
- 现在每次都要重新获取，浪费资源且容易失败

### 修复方案
建立**三级缓存体系**：

| 级别 | 数据类型 | 缓存时间 | 更新时机 |
|-----|---------|---------|---------|
| L1 | 实时价格 | 5分钟 | 盘中实时 |
| L2 | 技术指标 | 1天 | 每晚23:00 |
| L3 | 基本面 | 7天 | 每晚23:00 + 财报季 |

---

## 🔍 问题2：多数据源架构漏洞

### 现状
```python
# data_fetcher.py 中的数据源
- 腾讯（主）：基础数据 ✓
- 新浪（辅）：实时数据 ✓
- 东财（兜底）：技术指标 ✓
- AKShare：已移除 ✗

# 但 fundamental_data.json 中的数据
- 只来自akshare（已停用）
- 没有多源备份
```

### 问题
- 基本面数据（PE/PB/ROE）只有akshare一个来源
- akshare被移除后，基本面数据无法更新
- 浪潮信息(000977)的基本面数据还是3月6日的

### 修复方案
**恢复多数据源获取**：

```python
数据源优先级：
1. 实时行情：腾讯 → 新浪 → 东财
2. 技术指标：东财K线 → 本地计算
3. 基本面：东财财务 → akshare → 本地缓存
```

## 🔍 问题3：统一接口架构

### 当前架构图
```
data_fetcher.py
├── 实时行情 (5分钟缓存)
├── 技术指标 (无缓存，每次都重新获取)
└── 基本面 (akshare，已停用)

enhanced_fundamental.py
└── 基本面 (akshare，单独缓存)
```

### 问题
- 数据获取分散在多个模块
- 没有统一的缓存管理
- 重复代码多

### 修复方案
**统一数据服务架构**：

```
UnifiedDataService (统一入口)
├── 实时数据服务 (5分钟缓存)
│   ├── 腾讯API
│   ├── 新浪API
│   └── 东财API
├── 技术指标服务 (每日缓存)
│   ├── 东财K线
│   └── 本地计算
└── 基本面服务 (每周缓存)
    ├── 东财财务
    ├── akshare
    └── 本地缓存
```
